# What's new in v0.3

v0.3 is about one question: is this dataset ready to train on? The new [`audit`](../../reference/presets.md#audit)
preset answers it with a verdict that a training job can gate on.

Every workflow type is now a **preset**, a chain of evaluators, checks and transforms that you can read, copy and
change. You can also write chains of your own. Results come with an HTML report and with content digests that record
which data a run judged. `dataeval-flow serve` runs pipelines over HTTP as a preview. Flow now requires DataEval 1.2.1
and Python 3.11 or newer.

v0.3 breaks more than v0.2 did. Workflow types are renamed, `data-analysis` and `parameter-sweep` are removed, and every
workflow returns a `ChainResult`. Health thresholds move under `checks:`. A v0.2 config fails to load, and the error
names each key and type that v0.3 no longer takes. This page covers each change, and the {doc}`../changelog` lists every
old key and where it went.

The {doc}`../changelog` also lists the v0.2.2 to v0.2.5 patches. If you are upgrading from v0.1, read {doc}`v0.2`
first.

---

## At a glance

| Change | Impact | Action required |
| --- | --- | --- |
| Presets | Every workflow type is a chain of steps, and most types are renamed | Rename `type:`, and move thresholds under `checks:` |
| Audit verdict | One chain over train and its evaluation splits says whether to train | Replace `data-analysis` with `audit` |
| Custom workflows | You can chain evaluators, checks, transforms and presets yourself | None |
| Task matrices | A task can run over a grid of settings | Replace `parameter-sweep` with `matrix:` |
| HTML report | `result.html` shows thumbnails of the items a finding names | None |
| Provenance | A run records digests and manifests of the data it read, and `dataeval-flow verify` checks them | None |
| Service preview | `dataeval-flow serve` queues pipelines over HTTP | None |
| DataEval 1.2 | Missing metadata stays null, Outliers needs 20 items, and coverage uses DataEval's criteria | Recompute baselines |
| Python API | Results are `ChainResult` objects, internal modules are private, and imports move | Update imports and result readers |
| Platform | Python 3.11 or newer, no Poetry, and exit code `3` for health warnings | Update CI |

## Workflow types are presets

A preset is a workflow type whose settings expand into a chain of steps. Evaluators measure, checks judge what the
evaluators measured, and transforms make new datasets. A preset runs like any other chain, and you can run it as one
step of your own workflow. The {doc}`../../reference/presets` shows the chain of each preset. Run `dataeval-flow steps`
to list every step type with its ports and settings.

Each preset is named for the question it answers:

| v0.2 type | v0.3 type |
| --- | --- |
| `data-cleaning` | [`quality`](../../reference/presets.md#quality) |
| `data-analysis` | `audit`, described in the "Judge readiness with `audit`" section |
| `data-coverage` | [`scope`](../../reference/presets.md#scope) |
| `data-splitting` | [`splits`](../../reference/presets.md#splits) |
| `data-prioritization` | [`prioritization`](../../reference/presets.md#prioritization) |
| `drift-monitoring` and `ood-detection` | [`shift`](../../reference/presets.md#shift), which takes drift and OOD detectors in one `detectors:` list |
| `parameter-sweep` | A `matrix:` on the task, described in the "Compose your own chains" section |

Three presets are new. [`bias`](../../reference/presets.md#bias) judges class balance and how metadata factors relate to
the class. [`taxonomy`](../../reference/presets.md#taxonomy) judges labels against a declared ontology.
[`triage`](../../reference/presets.md#triage) finds metadata that a dataset failed to read, and recommends the policy
that repairs it.

### Upgrade a preset entry

A preset holds the settings of each step in a block named for the step. It holds the bounds of each check under
`checks:`, keyed by check type:

```yaml
# v0.2
workflows:
  - name: clean
    type: data-cleaning
    outlier_method: zscore
    outlier_flags: [pixel]
    health_thresholds:
      image_outliers: 5.0

# v0.3
workflows:
  - name: clean
    type: quality
    outliers: {flags: [pixel], outlier_threshold: zscore}
    checks:
      image-outliers: {warning: 5.0}
```

- A check warns only past its bound. It no longer warns on reaching it.
- Set `value_range` on the dataset entry, and move the `metadata_*` binning fields into a named `metadata:` policy.
- Presets use DataEval's default for every setting, with two exceptions. `prioritization` ranks `hard_first`.
  [`split`](../../reference/transforms.md#split) and [`kfold`](../../reference/transforms.md#kfold) hold out 20% for
  test, `split` also holds out 10% for validation, and both stratify.
- Findings are retitled for what they judge. Duplicates is now Image Duplicates, Label Distribution is Class Imbalance,
  and Embedding Coverage is Class Coverage. Update anything that matches on the title of a finding.
- Every preset returns a `ChainResult`. Read the output of each step under `result.steps`, as in
  `result.steps["outliers"].output`. The judgments of the checks are its findings. The result class of each type, such
  as `DataCleaningResult`, is removed.

The drift and OOD detectors of `shift` are evaluator entries now, so `method: mmd` becomes `type: drift-mmd`. The
{doc}`../changelog` lists every old key of every preset and where it went.

## Judge readiness with `audit`

`audit` runs one chain over train and each evaluation split, and gives a verdict: Not ready, Ready with caveats, or
Ready. Its report groups the findings under five questions and gives a next step for each warning. It also records the
items, classes, factors and digests of each split.

### Run and gate an audit

1. Name the splits in order, with train first:

   ```yaml
   workflows:
     - name: release-audit
       type: audit
       outliers: {flags: [dimension, pixel, visual], outlier_threshold: adaptive}
       accepted:
         class-imbalance: "Rare class by design; weighted loss in training."

   tasks:
     - {name: audit-splits, workflow: release-audit, sources: [train, validation, test], extractor: bovw_ext}
   ```

   `blocking:` names the check types whose warnings block training. `accepted:` records why you accept a warning.

2. Gate on the verdict. `--require` names the worst verdict that passes, and the command exits `4` when the verdict of
   a task is worse. `result: require:` and `DATAEVAL_REQUIRE` set the same requirement.

   ```bash
   dataeval-flow --config pipeline.yaml --output ./output --require ready-with-accepted-risks
   ```

`audit` also runs as a step of a custom workflow, after a step that made the splits. See
{doc}`../../how_to/gate_training_on_an_audit` and {doc}`../../notebooks/audit`.

## Compose your own chains

A `workflows:` entry with `inputs:` and `steps:` chains evaluators, checks, transforms and presets. Each step reads an
input, or the output of an earlier step, by its address, such as `cleaning.clean`:

```yaml
workflows:
  - name: cleaning
    type: quality
    outliers: {flags: [pixel], outlier_threshold: adaptive}

  - name: tidy
    inputs: [data]
    steps:
      - {name: cleaning, workflow: cleaning, input: data}
      - {name: dataset, transform: export, input: cleaning.clean, format: coco}

tasks:
  - {name: clean_export, workflow: tidy, sources: [train]}
```

v0.3 also adds these:

- Ten transforms: `view`, `merge`, `split`, `kfold`, `wrap`, `select`, `collect`, `remove`, `conform` and `export`.
  `remove` applies DataEval's removal plans, `conform` relabels onto an ontology, and `export` writes COCO, YOLO,
  Hugging Face or VisDrone. An `export` step after `quality` replaces `mode: preparatory`. The
  {doc}`../../reference/transforms` describes each one.
- A top-level `evaluators:` entry runs one evaluator. A task names it with `evaluator:` in place of `workflow:`.
- A `matrix:` on a task runs its entry once for each combination of the values it lists. The report opens with a table
  that compares the runs. The matrix replaces `parameter-sweep`.
- Plugins register workflows, evaluators, transforms, extractors and image transforms through entry points.

See {doc}`../../how_to/write_a_custom_workflow`, {doc}`../../how_to/run_a_matrix`,
{doc}`../../how_to/run_a_single_evaluator` and {doc}`../../concepts/WorkflowsAsChains`.

## Reports and exit codes

- `--output` writes `result.html`, a self-contained page with a card for each finding, sortable tables, and thumbnails
  of the items each finding names. `--no-report-images` turns the thumbnails off.
- The `result:` block names the result files and picks their formats: `json`, `text`, `html`, `junit` or `markdown`. It
  also sets their detail, the exit-code gate `fail_on:`, and limits on images and rows.
- A run that fails only on health warnings exits `3`. It exited `1` before, so CI can now tell it from a crash.
- The text report is 80 columns wide by default. It was 90.

See {doc}`../../notebooks/view_html_reports` and {doc}`../../how_to/read_evaluation_outputs`.

## Provenance

- `dataset_digest()` gives SHA-256 digests of the content and metadata of a dataset. The digests do not depend on the
  order of the items. The [`content-digest`](../../reference/evaluators.md#content-digest) evaluator records them in a
  run.
- A `content-digest` run writes a manifest of per-item hashes under `results/manifests/`. `dataeval-flow verify`
  compares a source with a manifest, and names the items that changed, went missing or were added:

  ```bash
  dataeval-flow verify output/results/manifests/audit-splits/content-digest-train.json --config pipeline.yaml --source train
  ```

- `provenance:` on a dataset entry records facts that Flow cannot measure, such as the owner, the license and the
  collection date.
- Every result records `library_versions` and the `device` its task ran on. An export records a digest of what it
  wrote.

See {doc}`../../concepts/Provenance` and {doc}`../../concepts/Reproducibility`.

## New steps, some experimental

v0.3 adds steps across the catalog. New evaluators include [`profile`](../../reference/evaluators.md#profile),
[`divergence`](../../reference/evaluators.md#divergence), [`completeness`](../../reference/evaluators.md#completeness),
[`factor-leakage`](../../reference/evaluators.md#factor-leakage), and five drift and two OOD evaluators. New checks
include [`leakage`](../../reference/checks.md#leakage),
[`class-sufficiency`](../../reference/checks.md#class-sufficiency),
[`untrained-classes`](../../reference/checks.md#untrained-classes) and
[`eval-coverage`](../../reference/checks.md#eval-coverage). The {doc}`../../reference/evaluators` and the
{doc}`../../reference/checks` group every step by the question it answers.

Some steps wrap DataEval features that are experimental themselves:

- [`sufficiency`](../../reference/evaluators.md#sufficiency) and
  [`performance-sufficiency`](../../reference/checks.md#performance-sufficiency) estimate how much training data a model
  needs. See {doc}`../../notebooks/measure_data_sufficiency`.
- [`feasibility`](../../reference/evaluators.md#feasibility) and
  [`performance-feasibility`](../../reference/checks.md#performance-feasibility) judge whether a performance target is
  reachable. See {doc}`../../notebooks/check_target_feasibility`.
- [`parity`](../../reference/evaluators.md#parity) and [`factor-parity`](../../reference/checks.md#factor-parity) find
  metadata factors tied to the class.

An experimental step may change or be removed in any release without a deprecation cycle. Each experimental step type
warns with `dataeval_flow.ExperimentalWarning` the first time a run in the process uses it. The warning subclasses
DataEval's `ExperimentalWarning`, so one filter silences both:

```python
import warnings

from dataeval_flow import ExperimentalWarning

warnings.filterwarnings("ignore", category=ExperimentalWarning)
```

## Run pipelines as a service

`dataeval-flow serve` is a long-running HTTP service. It queues pipelines and runs each one as the batch command would,
and it keeps the logs and result files of each run. It is a preview. Its API may change or be removed in any release
without a deprecation cycle.

```bash
pip install "dataeval-flow[service]"
dataeval-flow serve --data /path/to/data --output /path/to/service-output
```

Every image includes the service. See {doc}`../../how_to/run_flow_as_a_service` and the
{doc}`../../reference/service`.

## DataEval 1.2

Flow requires DataEval 1.2.1 or newer. Some of the changes in DataEval 1.2 reach the results of Flow:

- Metadata keeps missing values as null. A factor that mixes booleans with numbers or text is dropped as
  `mixed_types`.
- DataEval's Outliers fits a statistical threshold only to a population of at least 20. Below that,
  [`image-outliers`](../../reference/checks.md#image-outliers), `target-outliers` and `class-outliers` are not assessed,
  and they give DataEval's reason.
- [`class-coverage`](../../reference/checks.md#class-coverage) flags the classes that DataEval's Coverage flags. Its
  cutoffs are DataEval's `dispersion_factor`, `isotropy_factor` and `near_duplicate_threshold`. You set them on the
  `coverage` evaluator, or in the `coverage:` block of `scope` and `audit`. The check's own `dispersion`, `isotropy` and
  `near_duplicates` are removed. A near-duplicate fraction from an earlier run is not comparable with a new one.
- `drift-wasserstein` decides on the mean ratio over the dimensions, and its report says "Mean ratio".

See [Migrating from v1.1 to v1.2](https://dataeval.readthedocs.io/en/latest/migration/v1.2.html) in the DataEval
documentation.

## Python API

- `run(config, data)` runs one workflow or evaluator on in-memory datasets. `run_tasks` returns results keyed by task
  name, and calls `on_result=` as each task finishes.
- `result.output` replaces `result.data`, and `result.type` replaces `result.name`.
- Internal modules, such as `cache`, `stats` and `policy`, are private. Import config types from
  `dataeval_flow.config`, `load_config` and `run_task` from `dataeval_flow`, and `Finding` from `dataeval_flow.steps`.
- The typed task configs, `select_tasks`, `load_config_folder`, and the output and report models of each type are
  removed. Use `TaskConfig` for a task, and `load_config` to read a folder.

## Upgrade checklist

1. Install on Python 3.11 or newer, with uv, pip or conda. Poetry is no longer supported.
2. Rename the workflow types, as the table in the "Workflow types are presets" section shows.
3. Replace `data-analysis` with `audit`, and `parameter-sweep` with a `matrix:` on the task.
4. Move the thresholds under `checks:` and the step settings into their blocks, such as `outliers:`, `duplicates:` and
   `coverage:`. Move `value_range` onto the dataset, and the binning into a `metadata:` policy.
5. Update anything that matches on the title of a finding, such as a dashboard or a CI script.
6. Update the code that reads results. Read the `steps` and findings of a `ChainResult`, and `result.output`.
7. Update imports. Config types import from `dataeval_flow.config`.
8. Update CI. Exit code `3` means health warnings, and `--require` gates on the verdict of an audit.
9. Recompute baselines. DataEval 1.2 changes metadata, outlier and coverage results, and the metadata cache entries
   recompute on upgrade.
10. Treat the experimental steps as unstable. `sufficiency`, `feasibility` and `parity` may change in any release.
