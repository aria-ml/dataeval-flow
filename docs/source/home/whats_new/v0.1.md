# What's New in v0.1

v0.1 is the first public release of DataEval Flow. It contains the workflow orchestration framework, six evaluation
workflows, a TUI and CLI, the dataset adapters, a disk-backed cache, and signed multi-variant containers. The v0.1.1
and v0.1.2 patches added the parameter sweep workflow, Poetry and conda packaging, and a `ToRGB` preprocessor.

Nothing here is an upgrade. There is no earlier release to migrate from. If you are landing on this page while moving
to a newer version, go to {doc}`v0.2`, which is where the breaking changes start.

## Workflow orchestration

A pipeline is a configuration file, not a script. Datasets, views, extractors, and workflows are each named
once and referenced by name, and a `task` composes them. The task runner resolves the graph, executes each workflow,
and produces both a human-readable text report and a machine-readable result envelope.

### How to use

```yaml
datasets:
  - name: my_dataset
    format: image_folder
    path: data/my-images
    infer_labels: true

sources:
  - name: my_source
    dataset: my_dataset

workflows:
  - name: quality_check
    type: data-cleaning
    mode: advisory

tasks:
  - name: check_my_data
    workflow: quality_check
    sources: my_source
```

```bash
dataeval-flow --config params.yaml --data . --output ./results
```

The same config runs from Python through `load_config` and `run_tasks`. See the
{doc}`Quickstart <../quickstart>` and the {doc}`end-to-end tutorial <../../notebooks/end_to_end>`.

## The workflows

| Workflow | Type | What it produces |
| --- | --- | --- |
| Data cleaning | `data-cleaning` | Outliers, duplicates, and label issues |
| Data analysis | `data-analysis` | Statistical summaries and quality metrics |
| Dataset splitting | `data-splitting` | Stratified or random train/val/test splits |
| Drift monitoring | `drift-monitoring` | Per-batch drift flags and p-values, classwise optional |
| OOD detection | `ood-detection` | Per-sample out-of-distribution scores |
| Prioritization | `data-prioritization` | Ranked sample ordering for labeling |
| Parameter sweep (v0.1.1) | `parameter-sweep` | Per-configuration result comparison |

Each has a walkthrough under {doc}`Tutorials <../../tutorials/index>`.

## Interfaces

- The TUI is an interactive application for editing a config, launching tasks, and browsing results.
- The CLI is a headless runner plus a simple config builder for environments without a TUI.
- The containers are multi-variant images (CPU and CUDA), Cosign-signed and published to the Harbor registry. See
  {doc}`Run workflows in containers <../../how_to/containerized_workflows>`.

---

## Datasets and representations

- The adapters read HuggingFace, MAITE, TorchVision, ImageFolder, COCO, and YOLO sources.
- Embedding extraction supports ONNX inference. See
  {doc}`Use an ONNX model for embeddings <../../notebooks/onnx_embeddings>`.
- The cache is disk-backed and in-memory, so embeddings and statistics survive across runs. See
  {doc}`Reuse results with the disk cache <../../how_to/reuse_results_with_cache>`.

## Patch releases

### v0.1.1

- The parameter sweep workflow (`parameter-sweep`) runs a workflow across a grid of parameters and compares the
  results. Task matrices have since replaced it. See
  {doc}`Tune data cleaning with a matrix <../../notebooks/tune_data_cleaning>`.
- Poetry and conda packaging are added, alongside the existing pip and uv paths. Poetry support was dropped in v0.3.
- The package uses dynamic versioning via `hatch-vcs`.
- DataEval is bumped to v1.0.6, with logging patterns normalized against DataEval's own.
- HuggingFace dataset paths must include the namespace. A bare repo name no longer resolves.
- The `DataSplitting` workflow was not exported and could not be referenced from a config. This release fixes it.
- The CUDA 12.4 container variant is removed.

### v0.1.2

- The `ToRGB` preprocessor, in a new custom preprocessors module, coerces mixed-channel datasets to three channels.
