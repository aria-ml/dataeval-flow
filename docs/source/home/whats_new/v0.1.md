# What's New in v0.1

v0.1 is the first public release of DataEval Flow: the **workflow orchestration framework**, six **evaluation
workflows**, a **TUI and CLI**, the **dataset adapters**, a **disk-backed cache**, and signed **multi-variant
containers**. The v0.1.1 and v0.1.2 patches added the **parameter sweep** workflow, **Poetry and conda** packaging,
and a `ToRGB` **preprocessor**.

Nothing here is an upgrade — there is no earlier release to migrate from. If you are landing on this page while
moving to a newer version, go to {doc}`What's New in v0.2 <v0.2>`, which is where the breaking changes start.

| **TUI and CLI** | v0.1.0 | Interactive config editing and headless execution |

## 1. Workflow Orchestration

A pipeline is a configuration file, not a script. Datasets, views, extractors, and workflows are each named
once and referenced by name; a `task` composes them. The task runner resolves the graph, executes each workflow,
and produces both a human-readable text report and a machine-readable result envelope.

### How to use

```yaml
datasets:
  - name: my_dataset
    format: image_folder
    path: data/my-images
    infer_labels: true

sources:
  - name: my_source
    dataset: my_dataset

workflows:
  - name: quality_check
    type: data-cleaning
    mode: advisory

tasks:
  - name: check_my_data
    workflow: quality_check
    sources: my_source
```

```bash
dataeval-flow --config params.yaml --data . --output ./results
```

The same config runs from Python through `load_config` and `run_tasks`. See the
{doc}`Quickstart <../quickstart>` and the {doc}`end-to-end tutorial <../../notebooks/end_to_end>`.

## 2. The Workflows

| Workflow | Type | What it produces |
| --- | --- | --- |
| Data Cleaning | `data-cleaning` | Outliers, duplicates, and label issues |
| Data Analysis | `data-analysis` | Statistical summaries and quality metrics |
| Dataset Splitting | `data-splitting` | Stratified or random train/val/test splits |
| Drift Monitoring | `drift-monitoring` | Per-batch drift flags and p-values, classwise optional |
| OOD Detection | `ood-detection` | Per-sample out-of-distribution scores |
| Prioritization | `data-prioritization` | Ranked sample ordering for labeling |
| Parameter Sweep (v0.1.1) | `parameter-sweep` | Per-configuration result comparison |

Each has a walkthrough under {doc}`Tutorials <../../tutorials/index>`.

---

## 3. Interfaces

- **TUI**: an interactive application for editing a config, launching tasks, and browsing results.
- **CLI**: a headless runner plus a simple config builder for environments without a TUI.
- **Containers**: multi-variant images (CPU and CUDA), Cosign-signed and published to the Harbor registry. See
  {doc}`Run workflows in containers <../../how_to/containerized_workflows>`.

---

## 4. Datasets and Representations

- **Adapters** for HuggingFace, MAITE, TorchVision, ImageFolder, COCO, and YOLO sources.
- **Embedding extraction** with ONNX inference support — see
  {doc}`Use an ONNX model for embeddings <../../notebooks/onnx_embeddings>`.
- **Caching**, disk-backed and in-memory, so embeddings and statistics survive across runs. See
  {doc}`Reuse results with the disk cache <../../how_to/reuse_results_with_cache>`.

---

## 5. Patch Releases

### v0.1.1

- **Parameter sweep workflow** (`parameter-sweep`), running a workflow across a grid of parameters and comparing
  the results. See {doc}`the parameter sweep tutorial <../../notebooks/parameter_sweep>`.
- **Poetry and conda packaging**, alongside the existing pip and uv paths.
- **Dynamic versioning** via `hatch-vcs`.
- **DataEval bumped to v1.0.6**, with logging patterns normalized against DataEval's own.
- **HuggingFace dataset paths must include the namespace** — a bare repo name no longer resolves.
- **Fixed**: the `DataSplitting` workflow was not exported and could not be referenced from a config.
- **Removed**: the CUDA 12.4 container variant.

### v0.1.2

- **`ToRGB` preprocessor** in a new custom preprocessors module, coercing mixed-channel datasets to three channels.
